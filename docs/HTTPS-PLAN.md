# HTTPS 阶段的方向 review

基线：`b681429`，0.5.0-dev.0。范围只限新套件和专属本地测试。

## 判断

现有部署和恢复证据以本机 HTTP 为主。测试脚本按 origin 人工携带 Cookie，不能替代浏览器对 Secure、主机边界和跨应用回调的实际处理。部署器的入口健康检查也固定使用 HTTP。HTTPS 是团队自部署的必要入口，应先把这一层变成可验证能力。

## 本轮交付

1. 保留原 loopback HTTP / 外置反向代理模式；新增部署器管理 TLS 的可选入口。
2. 使用部署者提供的证书链、私钥及可选私有 CA；不申请真实证书，不更改 DNS、系统信任或现有浏览器。
3. 私有文件在部署目录中，镜像不含证书。验证主机名、有效期、证书链与密钥配对；校验失败先拒绝启动。
4. 三应用使用独立 HTTPS origin。入口准确保留 Host，并清理客户端伪造的代理头。内部身份通信保留原公开 issuer / 回调和独立服务签名。
5. HTTPS 健康探测连接本机发布端口，同时校验公开主机名和 CA；不关闭证书校验。
6. 完成登录、Kick → Makit → WeKnow、会话、附件、重启和新目录恢复；另检查浏览器实际 Cookie 与回调。
7. 覆盖错误域名、错误 CA、过期证书、不配对密钥、坏 Host、跨域写入和证书更新失败。
8. 测试结束清理专属进程、容器、网络和卷，核对原有运行容器 ID / 启动时间。

## 验收边界

测试 CA 仅供本轮隔离客户端信任。浏览器若使用精确测试证书公钥固定，需单独记录，并由独立 CA 校验客户端证明证书链，不能冒充公有 CA / 公网浏览器验收。

仍不处理跨机器 / 架构恢复、任意数据库迁移、真实外发、其余模块及公开发行。目标环境的公有 DNS、证书续期、入口防火墙和公网浏览器访问继续需要部署现场验证。
