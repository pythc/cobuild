# 自行 review · 源码整理

## 范围

新的本地 Git 仓库及来源哈希；五个工程的源码边界；构建/安装修正；目标配置校验；源码导入与发行工具。未修改原目录和线上服务。不是对全部继承业务代码的完整 review。

## 重点检查与处理

1. **导入失败留下半套源码**：改为先验证全部来源，再在私有临时目录复制与核对哈希，最后提交目标目录；异常仅清理本次创建的目录。基线清单用不覆盖已存在文件的方式提交。测试证明后续来源缺失时不会留下前一个组件。
2. **数据与密钥混入源码**：显式选择目录，拒绝符号链接，排除 .env、私有材料、数据库、依赖、构建产物和历史媒体安装包。扫描只输出规则/文件/行号，不输出匹配值。
3. **企业代码随派生版本公开**：排除整个 ee 和 base-formula 目录，保留上游核心许可；删除无效依赖与类型路径，并实际编译定位残留直接导入。完整发行许可审查仍为阻塞。
4. **安装隐式运行平台命令**：移除 Makit 顶层 postinstall 的妙搭初始化及自动 Git hook 设置；构建默认走 selfhost。验证安装使用 ignore-scripts，不能据此承诺所有外部依赖安装钩子已审查。
5. **构建越界打包排除产品**：Platform 的套件构建只编译现有内部应用，不调用桌面插件打包，也不构建实验室公开官网。包装器固定工作目录，避免从错误路径调用旧脚本。
6. **原依赖目录掩盖缺失**：所有组件独立安装；Relay 锁文件和 Nest 可选 peer 的缺项已用构建/测试复核。WeKnow 保持单独 pnpm 工作区，不合并互不兼容的根锁文件。
7. **配置看似生效**：配置工具明确返回 runtimeConfigured=false / runnable=false。可选模块名单是目标，不能把隐藏入口当服务端授权已经完成。
8. **临时数据库误删其他资源**：仅支持本地 Unix Docker endpoint、随机容器名与专属标签、随机 loopback 端口、不挂已有目录；清理前检查归属；异常仍删除临时凭据文件。实际数据库测试后容器已删除。
9. **凭据格式测试被误判**：仅对已查看的合成标记按完整原文件哈希登记；测试内容变化会重新触发扫描，不按 tests 目录整体放过。
10. **过早公开与错误回滚承诺**：根包保持 private，发行检查对未核实事项失败关闭；未发起 Git 远程推送。部署和回退文档要求保留新数据，不执行旧数据库恢复作为默认回退。

## 仍需处理

- `release-blockers.json` 中未完成事项均保留。
- Relay harness 包含面向既有批改服务的适配逻辑。该源码属于 Relay 本身，未导入批改产品；后续应抽为可选连接器，配置失败不得影响普通咨询与人工接待。
- Platform 仍是承载多个模块的原服务。没有为了目录美观复制另一套项目、成员或 HR 数据。
- 本阶段没有把旧域名批量替换成新域名。认证 audience、精确回调、Cookie、CSP 与 Origin 校验必须逐项重构并验证。
- 2776 份来源文件未改动，230 项指定测试通过；这些证据不能替代完整开源发行和部署验收。
- 首次全量导入的 Git 空白检查会报告既有源码、补丁和第三方许可文本的空白/CRLF。保留这些原始字节以核对来源，不批量格式化上游文件；本次新增和实际修改行另行检查。`.gitattributes` 关闭自动换行转换，避免检出后使来源哈希失真。

## 2026-10-27 · 通用运行时 review

本轮检查身份初始化、邀请的单次消费、密码哈希、私有文件权限、会话与 CSRF、PKCE 回调、应用角色、模块门禁、后台启动条件以及临时资源清理。不是对全部继承代码的完整审计。

已处理的问题：

1. Makit / WeKnow 回调后仍依赖飞书成员接口：新增独立本地身份映射，内部 UUID 不冒充飞书 ID；空库需组织所有者初始化，已有账号不按邮箱认领。
2. 平台角色可能覆盖业务角色：仅首个应用账号初始化管理角色，之后保持应用已有角色；真实数据库验证同名账号分离、显式停用不被重新激活、拒绝跨组织绑定及未迁移旧库。
3. 旧身份缓存延迟传播退出：本地模式每次检查统一会话，不启用旧的短时只读放行；实际退出 / 停用验证覆盖 Makit 与 WeKnow。
4. 开关只改变菜单：请求入口、应用跳转、MCP 工具及 scope、后台构造与定时器同步控制；关闭后旧令牌也不能访问；反复启停保留项目与账号。
5. 原域名通过侧边客服、品牌链接、登录提示或 MCP challenge 回流：本地模式关闭未配置客服，使用配置地址和本地认证提示；未完成的独立扩展在启动前失败关闭。
6. WeKnow 空库无法进入统一登录：仅为本地身份的状态、开始和回调开放初始化前路由，不开放旧的本地密码注册；创建真实工作空间后仍通过正常会话守卫。
7. 停用成员后无法恢复，或者恢复时重置原角色：管理查询与登录查询分开，恢复保留角色且旧会话不复活；停用成员同时撤销其尚未使用的邀请。
8. 邀请链接前端解析不一致：统一用 fragment 的 `token` 字段，读取后移除，避免进入 URL 查询和 Referer。
9. 临时数据库短暂启动状态被误当就绪：只等待 TCP 上最终 PostgreSQL 就绪，避免初始化 socket 返回成功后立刻遇到重启；测试失败仍清理专属容器。
10. 配置看似支持未完成模块：区分完整目标契约与当前本地运行能力；不支持的扩展、第三方身份、外发开关直接拒绝启动，没有伪装成可用。

新增迁移只添加本地绑定表，未重写原迁移。升级回退、旧库迁移、密码恢复、所有权转移、长期生产与全部业务流程仍待验证，发行门禁保持未通过。

## 2026-10-28 · 账号安全与项目协作 review

本轮只改新套件目录；复核了密码恢复、所有权转让、目录同步、签名服务边界、持久项目任务及本地需求 worker。原服务角色规则继续由各业务层检查。

1. **异步密码哈希期间身份改变**：登录、重新确认密码及修改提交前重新读取当前会话和用户状态，避免停用或并发重置后的旧验证结果继续生效。恢复令牌只存哈希、一次使用、最新替换旧链接。
2. **旧管理员留下可用恢复授权**：消费恢复链接时重新检查签发人和目标角色；停用、改密和所有权转让撤销相关会话、API 令牌、邀请、恢复令牌与待处理转让。所有权接收需要目标本人当前密码。
3. **统一角色被误当业务角色**：目录同步创建缺失普通成员，不覆盖 Makit / WeKnow 已有管理员和停用设置。平台所有权转让后，新所有者不会自动取得其他应用的管理员角色。
4. **服务接口成为匿名写入入口**：新增接口要求各应用独立私有签名、准确路径、组织、有效时间窗；拒绝浏览器 Origin / Fetch Metadata 和重定向；项目写入再次检查实时成员、应用入口和项目权限。业务请求 ID 和空间回执提供持久去重，协议 nonce 本身没有持久重放缓存。
5. **并发或重启产生同名空间**：WeKnow 使用组织 + 项目 UUID 主键、事务锁和同事务空间回执；重复调用返回同一 ID。原关联空间缺失时返回冲突。迁移 down 拒绝删除回执，不能默认回退数据库。
6. **空库启动但无法创建需求**：增加本地业务集合初始化，仅接受空库或兼容集合；不覆盖既有记录和字段。不兼容外部表绑定、缺失集合或错误字段类型在启动时拒绝。需求编号统一为至少 6 位并按编号查询真实操作记录。
7. **关闭外部任务也关闭了本地写入**：本地更新队列、历史和缓存处理独立运行；AI / 通知消费标记 `integration_disabled`，前端状态为 `disabled`，不把内部任务消费成功解释为外发成功。测试数据库中通知投递记录保持为零。
8. **异步操作使用失效权限**：Makit 后台重建操作者时经签名接口检查平台成员和应用访问权，然后继续应用本身权限检查；前端排队不是长期授权。
9. **临时环境遗留**：完整测试停止并重启真实服务，再根据持有的 Popen 和容器归属标签清理；不操作用户已有服务或数据卷。浏览器检查结束也释放本次环境。

联调中先后暴露了空业务集合、禁用本地 worker 和延后操作仍调用旧通讯录的问题，已修复并重跑。编号筛选回归曾因未重建 selfhost bundle 失败；另一次误用了需要独立运行管理员角色的全局记录接口，已改为操作者自己的进度筛选接口，保留原权限边界。不将失败轮次计入通过数量。

本地链路验收不等于正式发行。旧库迁移、项目完整生命周期、跨版本回退、附件恢复、Linux/HTTPS 部署、外部交付集成和继承代码的完整安全/许可审查均仍为待办。
