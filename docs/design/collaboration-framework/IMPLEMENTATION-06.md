# 第六批实现：项目成员与权限视图

日期：2026-10-29。版本：`0.11.0-dev.0`。基线：`eb434a0`。仅修改隔离的本地自部署套件。

## 1. Review 结论

先核对项目所有权、可见性和角色语义，见 [Review 06](REVIEW-06.md)。目前 Kick 项目对有应用访问权限的有效组织成员可见，Makit / WeKnow 仍独立核验业务权限。不能用一个“私有”按钮代替跨应用隔离，也不能把组织管理员等同于项目负责人或知识空间成员。

本批只补现状展示和前后端能力字段的一致性，不实施项目转让、可见性开关或新业务角色。后续转让的持久请求、确认、取消、过期与版本竞争列入 Review；管理员能否代发、原负责人是否保留为成员仍待确认。

## 2. 页面和实现

- Kick 项目详情新增“成员与权限”，与“概览”“管理”并列。组织身份与项目身份分别展示，注明 Kick 的现有可见范围以及 Makit / WeKnow 的授权边界。
- 复用已加载项目和会话，不新增 API、数据库、后台任务或依赖。没有逐项目请求其他应用，也没有将打开页面写成业务审计。
- 负责人排在成员名单首位，同一主体去重；邮箱可换行，长名单单独滚动并可键盘聚焦。仅显示现有成员资料，不推断额外身份。
- “当前可用入口”摘要与原管理页复用展示条件，不构成新的授权来源。里程碑待办的“完成”按钮改为使用后端逐项 `canChange`，缺失或为 false 时禁用；执行仍由服务端校验。
- `view=access` 随项目记录在 URL，支持刷新、前进与后退。沿用身份失效和项目撤权清理，避免继续展示旧名单或权限。

概览仍为默认视图；已有成员管理在“管理”中。权限摘要只读，不在本批扩展写操作。审批期间新增里程碑的既有 UI / API 口径差异保留为下一次业务确认事项，未扩大入口。
