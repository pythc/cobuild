## 后续顺序

第八批已完成宿主本地验证，见 [实施 08](IMPLEMENTATION-08.md)。当前默认关闭，容器网络仍保持隔离。

1. 下一批先 review 最小 Delivery 证据模型：绑定项目 ID、仓库原始 ID、PR、固定 SHA 和人工验收，不引入自动合并或部署。
2. 在需要容器使用公共代码来源时，单独设计和验证受控出网；不因一个只读来源直接解除整个核心网络隔离。私有仓库授权仍须先补读取权限和凭据边界。
3. 私有项目或更深聚合前补 Makit 稳定项目关联；发行前补最新候选干净构建、许可和资产、跨机器恢复。按实际需求选择待办、搜索或团队模板，不同时展开全部 D2–D5。

HiFlow、Evalab、荣誉、财务、考勤、通用聊天和大型低代码平台不做。旧路线图中的扩展应用列表是历史方案，不作为本轮缺口。

## 版本约定

- 根目录 `package.json` 和 `suite.json` 使用同一套件版本，并由测试检查一致性。
- 各组件自身的 `package.json` 保留原组件版本；不将其误称为整套 CoBuild 的版本。
- 每批增加 `IMPLEMENTATION-NN.md`，更新本页、根 README 和验证记录；保留旧实施记录，避免覆盖当时的验证结论。
- 不因文档或版本号变化自动关闭发行阻塞；不修改历史精确迁移计划的摘要。
