# 第二批实现：核心迁移与 WeKnow 受管空间

日期：2026-10-29。延续 `0.7.0-dev.0` 本地开发阶段。上一批记录保持历史原貌，本文件说明新增能力及当前边界。

## 1. 核心迁移

平台操作库增加显式 SQL 迁移和摘要历史。已有相同操作表可校验后接纳；结构冲突、未知历史或摘要变化会拒绝，不尝试猜测修复。DDL、历史和失败回滚处于同一 SQLite 保存点，原业务数据保留。

部署器增加 `core-managed-v1`，固定来源镜像、前后 schema 清单、审核计划和执行器摘要。停止写入后依次运行平台 SQLite 与 WeKnow PostgreSQL 步骤，分别提交各自历史。两库不是分布式事务：中途失败保留已提交前缀，由控制器读取实际历史决定恢复路径。

WeKnow 新表由 `weknow_owner` 创建，沿用其原生迁移归属；检查器也验证归属。用部署超级用户建表会导致“健康检查成功、实际文档请求 500”，因此不能只凭服务启动判定升级成功。

| 状态 | 兼容策略 |
| --- | --- |
| 尚无步骤提交 | 原版本可以恢复 |
| 部分提交 | 保持停止，保留数据、pending 和备份 |
| 全部提交 | 仅新 schema 可启动；不运行缺少新权限检查的旧版本 |

新增 `resume-upgrade` 复核原精确候选并继续未提交步骤，处理提交后控制器中断和启动前失败。恢复中检测到异常时停止本部署写进程，保留 pending。它不是替换任意修复镜像的接口。自动恢复不消费旧备份、不覆盖新数据，也没有破坏性的 down migration。

具体命令及兼容矩阵见 [部署说明](../../../deploy/README.md)。本次审核清单只对应证据中的基线与候选；未验证其他历史版本、跨 PostgreSQL 主版本或跨架构升级。

## 2. 受管空间边界

升级后 Kick 新申请创建且获批的空间，和项目映射在同一 PostgreSQL 事务登记为受管空间；初始不授予 Everyone 组访问。原有空间与原有映射没有回填，继续沿用原共享权限。手动关联既有空间也不会被自动接管。

受管空间实际授权为：

`有效统一身份 ∩ 应用访问 ∩ 有效项目成员资格 ∩ WeKnow 原生 ACL`

项目负责人初始获得空间管理员角色，项目成员初始获得写入角色。原生空间角色可进一步收紧；持续在项目内的成员被降为只读或移除空间角色后，下一次同步不会重新提权。撤出项目后保留原生 ACL 记录，但资格交集立即在下一次鉴权中拒绝访问；再次加入是一次新的资格授予。组织管理员身份本身不绕过成员条件。

| 项目变化 | 实际效果 |
| --- | --- |
| 加入有效项目 | 下一次请求核验资格，首次补充默认原生角色 |
| 从项目移除 | 下一次受保护请求拒绝；旧原生直接/组角色不能绕过 |
| 项目归档 | 全部项目成员失去该受管空间访问资格 |
| 恢复项目 | 按当前项目成员与原生 ACL 重新核验 |
| 停用身份或撤销应用访问 | 统一认证及应用门禁继续优先生效 |
| 项目改名 | 本批不自动修改 WeKnow 空间名；保留稳定项目/空间 ID |

资格通过带签名的内部接口查询，不接收浏览器自报权限。单用户的查询及落库在 PostgreSQL 锁内顺序执行，防止较早响应在撤权后重新覆盖资格；异常不会使用过期权限继续放行。

## 3. 覆盖的访问入口

- 页面、编辑、附件、OAuth/MCP：使用原生会话验证，并在原生 ACL 查询时叠加项目资格。
- 空间列表、页面搜索、数量及分页：先过滤资格再分页，不能仅隐藏导航。
- 公开空间与分享：受管空间不允许绕过身份开放。当前套件本来没有挂载分享创建控制器，因此创建端点测试的 404 不是服务内 ACL 分支已被端到端执行的证据。
- 实时文档与通知连接：每次入站消息重新验证；空闲连接每 5 秒发起复核，失败或权限变化后断开。网络故障仍受请求超时影响，**不是即时撤销所有在途出站消息**。推送式撤权尚未实现。

数据库资格有效期是辅助保护，不代替请求时的实时核验。多人和高并发负载仍需专门容量测试；目前没有吞吐量或最大组织规模承诺。

## 4. 验证与 review

机器可读结果见 [core-managed-checks.json](../../../provenance/core-managed-checks.json)。本批使用合成账号、独立数据和回环端口，没有访问线上业务或发送真实通知。

| 检查 | 范围 |
| --- | --- |
| 根测试与项目契约测试 | 迁移摘要、冲突回滚、身份、存储、命令回执和同步 |
| 部署策略测试 | 精确计划、前后指纹、提交前缀与禁止旧二进制回退 |
| WeKnow 定向测试 | 原生会话、协作连接、默认空间权限 |
| 三服务真实链路 | 受管空间、原生 ACL 收紧、移除/重加、归档、搜索、附件、真实 MCP 与协作连接 |
| 真实镜像升级演练 | 旧数据/会话、跨库部分失败、候选启动后注入控制器异常、继续升级、重启、拒绝旧版本和独立目录备份恢复 |

review 中修复了 SQLite 实际路径、WAL 辅助文件权限、新表所有者不一致，以及继续升级异常后残留写进程的问题；这些失败记录没有当作成功验收。升级 fixture 检查真实文档、附件和新命令写入，避免健康检查遗漏业务故障。此批控制器异常采用注入方式，没有声称完成本批迁移中的真实 SIGKILL 断电验证。

## 5. 未完成边界

- 旧共享空间主动转换、多个项目共管一个空间、项目负责人转让及空间改名联动。
- 更换故障候选镜像的通用向前修复协议，其他基线的受控迁移计划。
- 推送式权限撤销、长时间负载、跨机器灾备和此次版本的浏览器视觉验收。
- 通用事件投递/inbox、外部扩展隔离及其余设计阶段。

这些是本地工程验证，尚不是生产发布或开源发行验收。
