# 第五批实现：只读项目概览

日期：2026-10-29。版本：`0.10.0-dev.0`。基线：`173349d`。对象为隔离的本地自部署套件。

## 1. 设计复核与范围

本批复用 Kick 的项目、里程碑、空间链接和同步回执，以及 Makit 的现有需求查询和统计函数。跨源浏览器不能直接复用另一个应用的 Cookie，因此增加一个只读签名适配入口；沿用现有服务密钥，不新增身份提供方、数据库、队列或进程。

项目详情默认显示“概览”，原有写入操作保留在“管理”中。视图和项目 ID 写入 URL。目标取已有项目简介，不另增目标字段；展示负责人、里程碑完成数和近期节点、需求总数/进行中/已完成/阻塞/逾期、知识空间与项目同步状态。

当前只读空间关联和同步回执，不读取文档正文、附件、全库目录或空间原生 ACL。点击空间后由 WeKnow 核对权限。没有把同步回执作为在线健康检查或内容授权。

## 2. 读取与权限

1. Kick 内容先呈现，Makit 统计独立异步读取；只对当前选中项目请求，不逐项目预加载。
2. 浏览器调用当前同源的 `GET /api/workspace/projects/:id/overview/requirements`。平台先检查会话、项目读取与 Makit 应用访问；响应前再次检查。
3. Makit 的 `/openapi/suite/project-overview` 仅在通用本地身份模式接受现有签名服务连接。按组织和稳定主体查找已存在的有效业务账号，不创建账号、会话、角色或授权。
4. 复用需求查询的归档过滤、缓存新鲜度、项目别名归一化和状态统计。只返回统计与时间，不把整个需求集、人员目录或正文返回平台。
5. 旧需求仍按项目名称归类；服务端由稳定项目 ID 查名称，并对同名/交叉别名冲突拒绝统计，避免串数据。读取期间项目版本或名称变化时丢弃结果。尚未迁移为工作项直接持有稳定项目外键。
6. 来源为未启用、未连接、无权限、尚未同步、名称冲突或不可用时分别显示。错误不显示为 0，也不保留上次统计。真实空项目才显示 0。
7. 来源读取超时为 8 秒；切换项目、刷新和退出后拒绝迟到结果。读取期间撤权会丢弃结果，不让缓存越过授权。

“刷新需求进展”是读取刷新，不重试项目同步写入；现有需求缓存仍可能在其有效期内返回相同统计，页面显示来源时间和过期标识。

## 3. 部署与版本

无新增表或迁移，不改 schema 持有文件和既有精确迁移计划。统一根目录两处版本，计划入口改为链接 [当前实施状态](STATUS.md)。历史实施记录中的旧限制保留为当时事实，最新结论在本页和验证记录维护。

本批不发布线上，不改变其他本地服务，不推送公开仓库。独立部署、TLS、跨机器、x86_64、长期容量和公开发行并不由本批浏览器验收代替。
