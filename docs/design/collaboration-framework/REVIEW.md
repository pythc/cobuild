# 设计复核记录

日期：2026-10-28。复核对象：RFC 0.1 的主方案、研究、契约与实施计划。复核方式：同一作者自行 review，**不是独立第三方审计或实施验收**。

## 1. 范围检查

- 用户排除的 HiFlow、Evalab、荣誉、财务、考勤、通用聊天和大型低代码平台均未进入实施功能清单。
- 排除业务不等于删数据：原工程、历史源码来源、线上资料保持；后续发行剔除需要依赖审查。
- 默认核心仍为平台、Kick、Makit、WeKnow。Relay 等旧可选业务没有被重新包装成首发必做功能。
- 本轮仅新建设计文档，无运行配置、源代码、数据库、容器、权限或线上部署变更。

## 2. 当前事实与目标的区分

| 容易误判的内容 | 已采用的修正 |
| --- | --- |
| 本地已有源码等于通用版已可用 | GitHub / 通知代码与运行器集成门禁分开记录 |
| 三个服务必然是三个容器 | 明确当前默认一个 core 容器，逻辑边界不强行对应部署拓扑 |
| 统一登录就能访问全部业务 | 组织、应用、项目和原生资源权限取交集 |
| 模块声明是现成插件框架 | 清单、SDK、生命周期均标记为待实现 |
| 当前内部单次代码协议就是 OIDC | 内置协议保留适配，OIDC 仅作为新增外部 IdP 客户端 |
| 全员空间可以直接标记私有 | 新受管空间与旧共享空间分别设计，不隐式迁移 |
| 文档方案保证企业成熟度 | 设外部团队 / 扩展开发者 / 恢复验收，不提前宣称完成 |

## 3. 本轮修正的关键设计风险

### R1：受管项目空间创建时短暂全员可读写

要求空间、初始 ACL 和回执同事务建立，再返回成功。权限守卫覆盖原生页面、搜索、下载、API、MCP 和长连接。仅在工作台隐藏入口不算修复。

### R2：跨数据库权限检查存在竞争窗口

明确权限撤销前已提交事务不反向改变；新请求按最新资格。高风险核心动作需要协调屏障 / 写入许可。不能仅凭一次预检查宣称严格原子授权，长连接延迟必须实测。

### R3：聚合搜索和关系泄露私有信息

来源授权后返回结果，按权限隔离缓存；计数、摘要、相关资源标题也在范围内。来源故障不能使用旧高权数据凑完整结果。敏感附件使用当前授权代理。

### R4：事件与服务密钥被误用成业务授权

区分生产者命名空间、调用主体和当前用户权限。事件只报告事实，不能令消费者以管理员身份执行任意动作。第三方扩展不共享核心服务密钥。

### R5：停用模块后已发出的副作用无法撤回

生命周期区分停止新动作、排空和待核对结果。unknown 不能被当成 cancelled；停用和恢复不自动重发历史消息。

### R6：备份恢复让已发送消息重复发出

隔离恢复默认禁止外发；回执和防重记录属于恢复范围。先核对外部提供方，再恢复任务消费；无法核对时需人工处理。

### R7：审批流程变成大型低代码平台

只做版本化模板、有限字段、已注册动作与有界规则。没有任意 SQL / 脚本 / BPMN / 自由网络节点，不支持无限动态编排。

### R8：扩展框架先抽象、长期无业务落地

D1 先做一个真实项目命令、事件、投影的纵切；内置应用先采用接口。D5 再用独立扩展示例检验核心修改数量，而不是持续增加未使用的抽象层。

### R9：统一界面引入一次性前端重写

保持现有框架与专业编辑器。共享设计令牌、导航和 API，通过逐屏迁移验收。第三方远程代码不在工作台来源运行。

### R10：借鉴功能误当许可复用

研究仅采纳理念；开放核心、企业版功能和商业产品分别记录。WeKnow 派生许可门禁继续打开，没有擅自选择统一再许可。

## 4. 稳定性与成本复核

- 默认没有新增 Kafka、Elasticsearch、图数据库、Kubernetes、Temporal 或 Keycloak 的强制部署成本。
- 代价仍然存在：需要长期维护三应用适配、跨域权限、契约兼容和升级矩阵。不能将这些工作描述为低成本“一层封装”。
- 第一版不承诺高可用、活跃多写、零停机数据库升级或无限扩展数量。
- 候选容量和延迟数字明确是待验证目标，具体最低资源取决于后续测试。
- 实施分阶段关口，没有在缺少人员配置和实测工作量时编造交付日期。

## 5. 尚待实施验证的假设

1. 联邦搜索在目标规模下是否满足响应和可理解的排名要求。
2. 当前三应用权限接口能否以可接受开销完成实时资格检查，尤其附件和协作长连接。
3. 既有多数据库结构能否以 additive 方式引入所需 outbox / inbox / policy revision。
4. 声明式卡片 / 列表 / 深链是否满足第一批扩展，不提前开放任意 UI。
5. 外部团队是否接受项目为主、应用为次的导航；需可用性试用。
6. 当前私有工程所有代码 / 素材 / 依赖是否适合公开发行，需继续文件级许可审查。

这些不阻塞形成方案，但都阻止在没有证据时宣称实现完成。
