# 第四批实现：归档重试与项目页面状态

日期：2026-10-29。版本：`0.9.0-dev.0`。基线：`04f4ec1`，运行时基线为 `92bb055` / `0.8.0-dev.0`。按 [REVIEW-04](REVIEW-04.md) 实现，仅使用本地合成数据。

## 1. 改动范围

复用现有 operations、事件、两应用同步队列与数据库。没有新增表、服务、中间件、前端状态库或工作流引擎。

| 能力 | 本批行为 |
| --- | --- |
| 归档 / 恢复 | 注册独立动作与事件，业务修改和操作回执在同一事务内提交 |
| 丢失响应 | 同一表单重试复用请求 ID，返回原操作与当前项目，不重复业务修改 |
| 冲突 / 权限 | 同 ID 改输入拒绝；新 ID 配旧 revision 拒绝；回放和查询仍校验当前权限 |
| 部分完成 | Makit、WeKnow 分别保留投递状态；一个失败不会抹去另一个的成功 |
| 快速归档后恢复 | 消费者允许合并快照，回执标记 `snapshot-converged`，给出确认版本和最终归档状态 |
| Kick 导航 | 项目 ID 和筛选写入 URL；重载、刷新、前进 / 后退保持对象；归档直链自动匹配筛选 |
| Makit 导航 | 保留项目、搜索和阶段筛选；显式更改筛选 / 搜索清除原选择，避免显示不匹配的对象 |
| 编辑 | 后台刷新不替换表单草稿和文本焦点；项目列表重绘保留当前键盘焦点 |
| 失效状态 | 缺失或无权目标明确提示，不切到其他项目；暂时网络失败保留内容并提示；撤权清理旧详情及编辑草稿 |

旧客户端不传请求 ID 时仍可调用，但每次生成新 ID，不提供跨请求回放保证。表单草稿和重试 ID 不写浏览器持久存储；关闭表单或重载页面后不会恢复未提交草稿。URL 只保存导航状态。

WeKnow 回执中的确认版本可能高于命令提交版本：空间或 Makit 链接回填也会推进项目版本。旧回执成功表示该消费者已确认不早于原目标的快照，不表示每一个中间状态都实际执行。跨服务仍通过异步重试收敛，没有引入分布式事务。

## 2. 迁移与恢复

无新增 DDL，但两份持有 schema 的 store 源码变化会触发保守部署指纹。新增 `deploy/migrations/core-project-state-v1.json`，只接受保留的 0.8 基线到本批候选的精确摘要，要求既有迁移账本和执行器不变。旧计划保持原样；验证器显式列出允许的计划，不接受任意路径或任意代码变化。

仍使用现有备份、pending 和 `resume-upgrade`。新增语义不自动允许降级到缺少归档命令回放的旧版本。恢复验证使用不可变镜像，含坏运行时、修复候选替换、再次中断、继续升级和新目录冷恢复；不以“没有新表”代替实际验证。

## 3. 浏览器验收方式

`tests/project-state-browser.mjs` 由现有本地运行器的 `--with-browser` 启动。使用本机已安装 Chrome 的独立临时上下文、实际三服务、两个新建合成账号。浏览器和服务仅可连接本次 loopback 入口；不读取个人浏览器登录态，不调用实验室服务或真实通知。

覆盖表单错误、非空工作台待办、项目选择、编辑后台刷新、丢弃已提交 HTTP 响应再重试、归档 / 恢复、URL 历史、Makit 筛选与里程碑草稿、受管空间跳转、普通成员 API 拒绝、目标缺失、来源超时、键盘、390px 窄屏、403 缓存清理及实际角色降级。

状态型断言与人工查看截图分开记录。截图检查确认当前范围的弹窗文字、输入、按钮、筛选及窄屏排列可用；Makit 顶栏图标仍引用导入源码的旧托管地址，独立部署显示破图。这是后续品牌资源可移植性缺口，本批不将视觉结果记为全站无缺陷，也不扩大为品牌改造。

## 4. 自行 review 与修正

本次由同一作者复核，不是独立审计。

1. 检查了命令授权发生在回放前、请求指纹、同事务更新、旧租约拒绝、下游部分成功和最终版本回执。
2. 检查了页面选择与筛选的一致性、缺失目标不回落、后台刷新不改草稿、撤权清理及迟到提交响应不恢复旧身份界面。
3. 自查发现项目焦点处理误插入待办列表，非空待办可能引用未定义变量。已删除错误代码，并加入非空待办的单元和真实浏览器回归；最终重跑通过后才记为验收。
4. 最初恢复演练与另一套自有测试并行，其他容器清单因后者正常清理而变化，整体报告为失败。保留该失败证据，最终恢复演练改为顺序执行；不把阶段断言通过冒充整体通过。
5. 浏览器早期驱动选择器与旧缓存构建导致的失败不计入通过；最终构建、截图和报告以最后一轮为准。
