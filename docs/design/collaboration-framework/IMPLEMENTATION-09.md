# 第九批实现：Makit 评审控制与自测报告

日期：2026-11-21。基线 `6d0035b` / `0.13.0-dev.0`，本批 `0.14.0-dev.0`。按用户确认，将生产比对快照中的两项修复回补到本地通用套件。仅提交私有开发仓库，不操作生产服务、不公开发行。

## 1. 回补边界

回补前核对两个目标服务文件与套件导入基线一致；仅引入 AI 评审服务、发布检查服务及新共享报告解析文件，不覆盖整个生产工程。对照快照的三份 SHA-256 记录在 [机器可读摘要](../../../provenance/makit-review-backport-checks.json)。未导入生产配置、数据、凭据或构建产物。

平台原生账号、组织、模块启停、项目命令与转让、Makit 原生存储适配以及 WeKnow 受管空间实现保持。修改仅涉及上述报告/评审代码、运行器变量映射、测试和版本文档。没有 schema、SQL 迁移或额外运行依赖。

## 2. 最终行为

### 2.1 独立关闭 AI 评审

- Makit 增加独立环境变量 `MAKIT_AI_REVIEW_ENABLED`。值为 `false` 时，不启动 AI 恢复定时器，不排队、领取任务或调用模型；不以停用全部 worker 代替。
- 手动重试先核对用户写权限，再明确返回 503「AI 评审已停用」；批量触发列出跳过原因。有效流转跳过 AI 评审条件，非法流转与必填研发资料仍受检查。
- 不删除入口、队列、历史评审或研发资料，资料仍能保存。未设置或 `true` 的独立 Makit 保留旧行为。
- 两个套件运行器均复用 `integrations.ai` 映射此变量，不新增公共配置或放开外发。目前通用运行时仍拒绝启用外部 AI；这不是已完成的模型集成。

### 2.2 页面与发布检查统一读取报告

`self-test-report.model.ts` 提供只读解析和内容有效性判断。页面及发布检查优先使用 `requirement_artifact.self_test_report`，不存在时兼容旧 `selfTestReport`，读取本身不触发回填。

已存在的新资料即使为空或不可读，也具有优先级；不能用旧报告掩盖。纯空模板、空 HTML 和不可读链接不通过。读取异常直接传播，不伪装成旧字段成功。迭代没有启用自测检查时不额外查询报告。

AI 开关与发布就绪检查独立：关闭 AI 不会放过缺失自测报告或发布负责人等条件。补齐发布检查 SQL 引用，避免运行时 `sql is not defined`。

## 4. 自审、资源与版本管理

1. 复核关闭点覆盖自动触发、手动触发及最终模型边界；权限检查保留，其他队列不受该开关控制。
2. 复核资料优先级、读取期间异常、旧字段兼容均不写回；未新增数据库迁移。
3. 保留失败日志；三应用真实回归验证通用改造没有被生产文件覆盖。
4. 测试容器和本轮应用进程自动清理；原有 15 个容器 ID / 启动时间未变。本轮开始前已运行的本地预览保持不动。
