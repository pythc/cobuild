# 第七批 Review：项目负责人转让

基线：`cf37a89` / `0.11.0-dev.0`。仅本地自部署核心套件。

## 已确认的规则

- 用户确认：负责人或组织管理员可发起；接收人必须本人确认。
- 用户确认：原负责人保留为普通项目成员，不改变其里程碑归属。
- 接收人限现有有效项目成员。审批中、已归档、待完善项目不接受转让；请求 24 小时有效，双方及当前管理者可取消。
- 发起、接收、取消均绑定请求编号；项目 revision、人员启用状态和发起人当前资格在接收时重新核验。过期或项目资料变化后重新发起。
- 不改 WeKnow 原生 ACL。双方都已经是项目成员，交换负责人不等于转让知识空间所有者；Makit 更新项目快照，WeKnow 保留原空间映射和原生角色。

## 实现边界

复用现有工作区 SQLite、事务、持久命令回执、目录和项目同步队列。新增一张请求表及显式迁移，不新增进程、缓存服务或通知渠道。先提供项目页面与工作台待办，不自动发外部消息，不将本批标为私有项目或细分角色实现。

## 易错场景与验收

1. 只能本人接受，不允许管理员代接受；客户端提供的姓名、邮箱和角色均不作为授权。
2. 接收事务同时更新负责人、成员、revision、审计及同步队列；响应丢失后按原请求恢复结果。
3. 同时发起只保留一项有效请求；过期、取消、重复接收、跨项目 ID、停用、撤权、成员移除和原项目变更需拒绝或显示失效。
4. 本机真实浏览器覆盖发起、取消、接收及状态刷新；受管空间和原里程碑不丢失。
5. 追加迁移必须保留旧迁移摘要，核验旧数据、请求重启持久化、失败后继续升级与旧版本拒绝；测试只使用隔离资源。
