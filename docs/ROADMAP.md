## S1 · 独立配置与部署

以 `provenance/audit.json` 的实际定位逐项改造；测试夹具、文档示例与执行路径分别判断，不批量替换整个仓库。

- 将公共地址、品牌、组织、邮箱和服务连接接入配置层。
- 明确服务私有 secret、首次生成过程、权限和备份范围。
- 应用默认不连实验室域名；未配置的集成显示可操作的配置提示。
- 在干净环境完成独立依赖安装和构建；提供锁定镜像与 Compose。
- 验收：禁用所有集成时，核心启动并健康，不请求任何 110 实验室服务。

## S2 · 本地身份与权限

- 首个管理员用一次性初始化流程创建，不设置默认密码、固定邮箱或固定姓名。
- 本地登录、邀请、退出与凭据恢复；设置密码的凭据不经日志或聊天输出。
- 对接现有各应用的服务会话，保留即时成员检查与业务授权。
- 飞书可选，OIDC 后续接入；账号关联需要本人确认，不能按同名/同邮箱自动合并。
- 验收：管理员和普通成员完成网页与 API 权限正反例，重开保持登录，退出后失效。

## S3 · 统一项目与可选模块隔离

- Kick 持有唯一项目，Makit 使用稳定关联，WeKnow 建空间有持久化回执。
- 迁移既有关联，不破坏原需求、文档、候选人及评审记录。
- 可选模块的 API / MCP / worker 与页面同步启停。
- 验收：重复请求、网络中断、任务重试不会重复创建项目或空间；停用模块不产生通知或外发。

## S4 · 核心完整流程与首个发行候选

- 用独立测试组织、两个测试用户和示例项目完成主线，不复制团队业务数据。
- 覆盖备份恢复、兼容升级、失败回退、附件、搜索和退出。
- 明确正式最低资源要求，使用实际测量数据，不能用当前服务器配置推算。
- 收齐测试/构建/恢复证据，逐项关闭 `release-blockers.json`。
- 再准备公共仓库、镜像、版本说明、贡献指引与安全反馈渠道。

## S5 · 扩展发行

HiFlow、Evalab、Relay 按独立验收矩阵开放；飞书、邮件、GitHub、AI 按连接器文档开放。发行时明确启用成本、权限与数据边界。
