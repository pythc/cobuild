# CoBuild 产品与架构边界

## 使用对象与主线

第一阶段面向一个组织自行部署，用于实验室和小型研发团队。默认完成“组织与成员 → 项目 → 文档 → 需求与迭代 → 交付记录”。不在第一阶段引入 SaaS 租户计费、公共注册市场或跨组织运营。

## 项目与知识的关系

- 平台 / Kick 是项目 ID、名称、状态、负责人、项目成员与里程碑的权威来源。
- Makit 拥有需求、任务、迭代和交付记录。其项目视图引用平台项目 ID，不能因为同步失败另造项目。
- WeKnow 拥有空间、文档、附件与文档内部权限。项目保存明确的空间 ID 和链接，不按同名推断关联。
- 项目创建可选择建立文档空间；小团队可直接创建项目，立项审批是可选流程。
- 创建空间等跨服务操作使用持久化任务、幂等键和回执。成功部分保留，仅恢复失败的后续步骤。
- 角色和状态变化重新检查权限，异步投影不能单独作为授权依据。

## 身份与权限

目标是由平台管理内部用户 ID 与组织成员关系。外部身份以 provider + provider subject 映射到内部 ID，飞书邮箱和显示名不能代替稳定 ID。现有业务 ID 保留，通过映射迁移，不能重新生成 ID 导致历史记录断链。

基础账号、邀请和首次管理员初始化应在没有飞书时可用。飞书、OIDC 属于可选连接；每个部署配置自己的回调与凭据。保留现有 PKCE、state、单次授权码、CSRF 与 Origin 校验，改域名时不能只替换字符串。

组织管理员、项目负责人、HR、面试官、邮箱授权人、知识空间管理员分别授权。登录同一账号不等于获得所有业务写权限。默认普通成员仅能按项目/空间权限读写；招新模块继续限制非 HR、非管理员读取自己负责的候选人，以及填写自己的面试安排与面评。

## 模块启停

`suite.json` 当前定义目标模块和依赖；不是运行时执行器。真正启停需要逐层落实：导航和路由、业务 API、MCP 工具、worker、定时器、邮件/机器人消费均由服务端控制。

模块关闭时保留历史数据，不启动其作业，不自动删除数据库。重新启用需校验配置和迁移。界面隐藏不能替代权限检查。

## 技术与服务边界

- 产品导航、品牌、通用表单和错误反馈逐步统一；现有 Vue、React 和原生 JavaScript 不在源码整理阶段重写。
- 门户内部模块先维持模块化单体。Makit、WeKnow、Evalab 与 Relay 保留服务边界。
- 每个服务拥有自己的数据和迁移权限，不通过其他服务的数据库进行跨域写入。
- 公共配置管理域名、模块和身份提供方；凭据使用部署者的私有环境/secret 文件，不写入配置示例。
- 核心网页与服务 API 独立于桌面插件。统一 MCP 可作为 API 适配层保留，发行插件不是核心部署前提。

## 可选模块

- HiFlow：招聘/招新流程；候选人数据与一般项目资料分开授权。
- Evalab：可独立启用的考核业务；可由 HiFlow 关联，但不依赖必须开启招新。
- Relay：咨询与反馈，可显式关联 Makit 需求；AI 接待默认关闭，费用由部署者自己的连接承担。
- 荣誉、动态发布：实验室特色模块，默认关闭。
- 邮箱：提供授权、模板和业务邮件能力；不在第一版发展为通用邮件服务器。
- Pulse：管理员运维入口，不与普通成员日常协作争夺主导航。
