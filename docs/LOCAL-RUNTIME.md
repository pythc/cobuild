# 通用身份与项目协作 · 本地验证版

版本：`0.13.0-dev.0`。2026-10-30。本页描述宿主 Node 的开发运行。容器独立部署与恢复工具见 [部署说明](../deploy/README.md)；均不操作现有线上服务。

## 1. 已接通的范围

| 能力 | 本轮结果 |
| --- | --- |
| 统一身份 | 不配置飞书即可初始化组织所有者、邀请成员、登录和退出；密码使用 scrypt，账号使用内部 UUID |
| 会话 | HttpOnly Cookie，默认 30 天，取自公共配置；重启保持登录；统一退出或停用成员立即使 Makit / WeKnow 旧会话失效 |
| 跨应用 | 真实 Platform、Makit、WeKnow 通过一次性代码、PKCE、精确回调和后端检查建立各自会话 |
| 业务角色 | 应用保留各自角色；仅全新空库首次由组织所有者创建应用管理账号；已有账号不按邮箱自动合并 |
| 通用配置 | 平台读取 `COBUILD_CONFIG`；核心应用的非敏感运行变量由同一配置映射；数据库密码和加密密钥分开保存 |
| 可选模块 | 仅支持四个核心模块，按依赖启停；排除业务模块不可配置启用，页面/API/MCP 拒绝访问，招新待办库不再创建 |
| 数据保留 | 关闭模块不会删除数据；重新启用继续使用同一个数据目录；旧令牌不能绕过模块关闭 |
| 组织页面 | 独立的组织成员页，可邀请成员、调整组织管理员、停用和恢复成员；不进入旧公共邮箱管理员页 |
| 账号安全 | 修改密码、管理员协助恢复、部署者恢复所有者；变更密码撤销所有设备和关联应用的旧会话 |
| 组织所有权 | 所有者发起、接收成员确认，两端验证当前密码；完成后原所有者转为组织管理员 |
| 完整目录 | 成员无需先登录业务应用即可被选中；Makit 在读取目录时同步，WeKnow 每 15 秒同步，保留各应用已有业务角色 |
| 项目协作 | Kick 创建与审批、Makit 同步项目和回写里程碑、WeKnow 自动建空间并回填链接；同一项目重试不重复建空间 |
| 只读概览 | Kick 项目详情默认汇总目标、负责人、里程碑、Makit 需求进展及知识空间关联；各来源独立显示错误，管理操作在“管理”视图 |
| 成员与权限 | Kick 只读展示组织身份、项目身份、现有可用入口及去重成员名单；复用项目数据，无额外接口，视图保留在 URL |
| 公共代码来源 | 默认关闭；手动读取项目公共 GitHub 仓库和 PR head 检查；无凭据、无代码写入 |
| 本地需求 | 空库自动建立需求、迭代、评论和验收等业务集合；本地更新队列与操作历史执行，未配置的 AI 和通知显示未启用 |

模块开关在进程启动时读取，修改后需重启；当前不提供热更新。恢复成员不会复活其已失效的旧会话。

组织所有者、组织管理员和普通成员是平台角色。Makit / WeKnow 的已有业务角色不会随平台角色升降而被覆盖。退出某个应用只结束该应用会话；从工作台退出统一身份，会使其所有关联会话失效。

## 2. 本地平台预览

前提：Node.js **24.x**，平台依赖已独立安装。首次构建：

```sh
npm --prefix apps/platform run build
npm run local:init
npm run local:platform
```

`local:init` 只创建新的 `.local/development/config.json`，不会覆盖已存在的配置；分配本机端口，默认仅启用平台与 Kick。启动日志给出本机入口，初始化页面可创建自己的组织所有者。

第一次启动生成 `.local/development/data/bootstrap.private.key`。在部署机器上私下读取并填入初始化页面，创建后自动删除。凭据不要提交 Git、发到聊天或放进 URL。没有默认姓名、邮箱或密码。

这是**平台 / Kick 预览**，不会悄悄启动其他服务或数据库。自定义目录时必须同时指定：

```sh
COBUILD_CONFIG=/absolute/private/config.json \
COBUILD_DATA_DIR=/absolute/private/data \
npm run local:platform
```

启动器只监听 `127.0.0.1`，要求明确的本机 HTTP 端口；自带 Node TCP 连接限制，默认阻断非本机地址；显式启用公共代码来源后，仅额外允许 `api.github.com:443`。它不是生产启动器。

### 2.1 启用公共 GitHub 代码状态

在本地私有配置中增加下面这一项，并重启自己启动的预览服务；不改变 `integrations.github: false`。旧配置没有此项仍可运行，默认关闭。

```json
"codeSources": { "githubPublic": true }
```

1. 在 Kick 项目的“管理”中填写 `https://github.com/组织或用户/仓库`（可带 `.git` 后缀），保存。
2. 打开“概览 → 代码状态”，点击“加载代码状态”。最多显示最近更新的 5 个 PR。
3. 点击“查看检查”，按该 PR 的固定 head SHA 读取 check runs 与 commit statuses；最多各 20 项。部分、未发现、失败和不可用分别显示，均不替代人工验收或部署状态。
4. 手动刷新遵循 60 秒缓存；页面标出读取时间和缓存状态。检测到 head 变化时刷新代码状态可获取新的提交。没有后台轮询，触发限流后等待提示再重试。
5. 关闭该开关或 Kick 后重启进程，不再读取来源，内存缓存清除；项目仓库链接、账号和业务数据保留。

适配器只向固定 GitHub API 发 GET，不发送 Cookie、访问令牌，不读取环境中的 GitHub 凭据，也不跟随仓库重定向。仓库迁移后需人工确认并更新链接。私有仓库不在本批范围；当前项目仍组织内可见。

本地网络守卫只在 Kick 启用、所有旧集成关闭且外发关闭时允许上述固定主机及端口。此例外已用真实浏览器和公共 API 验证。**容器核心网络仍为 `internal: true`，本批未配置容器出网，因此不能将宿主预览互通当作容器连接验收。** 需要容器使用时先单独实施受控出网，不直接解除网络隔离。

## 3. 完整核心链路测试

前提：Platform、Makit、WeKnow 已构建；本机 Docker 通过 Unix socket 运行，并已缓存 `postgres:17-alpine` 和 `redis:8-alpine`。WeKnow 保留自己的 pnpm 工作区。

```sh
npm test
npm run test:local-suite
```

`test:local-suite` 会：

1. 创建随机名称、专属归属标签、仅本机随机端口的 PostgreSQL / Redis；不挂已有卷。
2. 使用临时私有文件和随机密码，建立全新 Makit / WeKnow 数据库，执行迁移；Makit 使用独立受限运行角色。
3. 从同一份通用配置生成两套应用环境，启动三套真实本地服务；启用必要的本地写入队列，关闭外部 AI、邮件与飞书通知，阻断服务进程的非本机 TCP 连接。
4. 创建两个合成账号，验证登录、邀请、目录、角色边界、PKCE 错误和重放、跨应用会话、统一退出、停用与恢复、密码恢复和组织所有权转让。
5. 创建项目并审批，自动同步 Makit 和 WeKnow；创建需求、分配成员、更新进展、评论和验收；回写里程碑、保存知识文档，验证重复请求、越权与过期版本。
6. 停止并重启三个服务，使用同一测试数据验证账号、权限、项目、需求、文档及空间回执的持久性。
7. 停止本次进程，按归属标签删除本次容器和临时目录。清理失败会使测试失败。

测试不会真实发邮件、联系飞书、读取现网账号或访问原实验室后台。结果写到忽略提交的 `.local/native-core-result.json`；测试报告只保留状态，不输出密码、Cookie、授权码或令牌。

`tests/suite-runtime.test.mjs` 另行完成“关闭 → 开启 → 关闭 → 再开启”，实际检查 HTTP、MCP、持久会话、项目数据以及关闭状态。不是只测试菜单隐藏。

需要人工检查浏览器时可运行 `npm run test:local-suite -- --browser-review`。它在自动检查和重启检查通过后保留环境，最多 15 分钟；本机 `.local/browser-review.json` 给出入口与 `releaseFile`。检查结束后创建该标记文件，测试器就会清理本次环境；超时也会清理并报告失败。不要把测试账号或临时链接用于真实业务。

自动真实浏览器验收使用 `npm run test:local-suite -- --with-browser`，需显式设置 `COBUILD_PLAYWRIGHT_MODULE` 为已安装 Playwright 的入口绝对路径、`COBUILD_CHROMIUM_EXECUTABLE` 为本机 Chrome 的可执行路径。驱动不自动下载浏览器、不使用个人配置，报告和截图写入 `.local/project-state-browser/`。失败同样清理本轮服务。不要与恢复演练并行，否则资源清单比较无法分清其他自有测试的正常启停。

## 4. 配置如何作用到服务

公共配置契约在 `packages/config/index.mjs`；运行时路由和工具门禁在 `packages/config/runtime.mjs`。配置须有组织名称、公共地址、模块列表、本地身份和会话期限。

`packages/config/local-environment.mjs` 将配置映射为 Makit / WeKnow 的实际非敏感变量；未启用的服务返回 `null`，启动工具必须跳过。它不会生成或打印服务密码。

持久化边界：平台的身份、统一授权、应用访问规则和业务 SQLite 位于指定数据目录；Makit / WeKnow 使用独立数据库；WeKnow 附件路径必须显式指定。测试使用可删除的临时目录，平台预览使用持久目录，不能混用。

启用 Makit / WeKnow 时，平台在私有数据目录首次生成 `makit.service.key` / `weknow.service.key`，权限为 `0600`。对应应用通过 `COBUILD_SERVICE_KEY_FILE` 读取各自文件；测试器自动完成映射。服务协议绑定请求路径、组织和 60 秒时间窗，拒绝浏览器来源与重定向。nonce 不提供跨重启的去重存储；写入去重依靠项目请求 ID 和数据库持久回执。

Makit 的首次业务集合初始化仅接受空库，或同组织、同集合 ID 且字段兼容的本地库；不会覆盖现有字段和记录。不兼容的旧库必须先设计迁移。历史 `FEISHU_*_TABLE` 变量名仅作为内部兼容映射，本地模式指向 PostgreSQL 的 `suite-*` 集合，不需要飞书表格。

## 5. 账号恢复与组织所有权转让

工作台左下角账户菜单进入「账号安全」，也可访问 `/account`。

1. **修改自己的密码**：填写当前密码与新密码（12–128 字符）。成功后需重新登录，其他设备及关联应用的旧会话也失效。
2. **恢复成员账号**：组织管理员可以为普通成员生成恢复链接；所有者还可以为组织管理员生成链接。必须输入操作者当前密码，不能通过此入口重置自己或组织所有者。链接 30 分钟有效、只能使用一次；重新生成会替换旧链接，不自动发邮件。
3. **转让组织所有权**：所有者选择另一名启用成员并输入当前密码。接收人在 24 小时内进入自己的「账号安全」，验证本人密码后确认；任何一端都可以取消。完成后双方旧会话失效，原所有者成为组织管理员。Makit 管理员、WeKnow 所有者等应用角色不会自动跟随转让。
4. **所有者忘记密码**：具有部署机器私有数据访问权的维护者执行下面命令。它只向数据目录的 `0600` 私有文件写入一次性链接，终端仅显示文件路径与到期时间；私下打开后交由所有者本人设置密码。使用后删除该临时恢复文件。

```sh
COBUILD_CONFIG=/absolute/private/config.json \
COBUILD_DATA_DIR=/absolute/private/data \
npm run local:recover-owner
```

该命令拒绝不存在的身份库，要求恰好一个启用的组织所有者；不能替代对旧数据库的身份迁移。管理员失权或停用后，其未使用的恢复授权不能继续生效。

## 6. Kick → Makit → WeKnow 操作流程

完整三服务环境中，先由组织所有者分别连接一次 Makit 和 WeKnow，建立新库的应用绑定；成员随后使用同一个 CoBuild 账号连接即可，不需再创建业务密码。首次初始化与普通成员登录是不同权限。

1. 在组织页面邀请成员，成员接受邀请后进入组织目录。业务应用同步该目录，不要求每个人预先登录每个应用。
2. 在 Kick 新建项目，填写负责人、成员和简介；需要文档空间时勾选「创建独立 WeKnow 项目空间」。新项目先进入探索阶段。
3. 提交立项并由有权管理员审批。通过后，持久任务同步 Makit 项目，并在 WeKnow 创建同名空间；项目使用同一个稳定 UUID，空间保存独立 ID 与回执。
4. 在 Kick 或 Makit 打开项目。Makit「管理里程碑与空间」可以添加或调整里程碑、编辑知识空间链接；后端按 Kick 的项目权限和 revision 检查，成功后回写同一份数据。
5. 点击「查看需求」进入该项目筛选，创建需求并选择组织成员处理。可修改进展和开发工作量、发表评论、添加和完成验收项。异步写入和历史记录在本地执行，重复提交返回原操作。
6. 点击「WeKnow 空间」进入对应空间，创建项目设计和协作文档。Native 新建受管空间同时检查当前项目成员资格和 WeKnow 原生权限，组织管理员不会自动获得所有空间的文档权限；归档期间暂停受管空间访问。历史共享或手工关联空间不自动转换。
7. 重试自动创建只返回原空间。已关联空间不可用时返回冲突，需要恢复或处理原关联，不再创建同名副本。新空间链接会回填 Kick 并同步 Makit。

项目名和显示链接不是身份键；服务关联以平台 UUID 和空间 ID 为准。已在本地验证创建、审批、里程碑、文档与需求协作、受管空间权限，以及改名和归档 / 恢复的收敛。归档命令回放与导航状态见 [第四批实施记录](design/collaboration-framework/IMPLEMENTATION-04.md)，只读概览见 [第五批实施记录](design/collaboration-framework/IMPLEMENTATION-05.md)，成员权限视图见 [第六批实施记录](design/collaboration-framework/IMPLEMENTATION-06.md)，当前缺口见 [实施状态](design/collaboration-framework/STATUS.md)。

项目详情默认进入“概览”，切换“成员与权限”查看身份和名单，切换“管理”使用已有编辑入口；项目和视图保存在 URL。概览的需求统计沿用 Makit 的状态口径，排除已归档需求，读取当前用户已连接的账号；尚未连接、没有权限或来源不可用时显示对应状态，不用 0 代替错误。空间区只显示已有链接与同步回执，打开后由 WeKnow 核对内容权限。

当前 Kick 项目对拥有应用访问权限的有效组织成员可见，尚无私有项目。成员视图不授予权限：组织管理员不等于项目负责人，也不自动拥有 WeKnow 文档访问权。待办里的里程碑按钮遵循后端逐项返回的 `canChange`；执行命令仍由后端核验。可见性和细分角色未实现。

在“成员与权限 → 负责人转让”选择现有有效项目成员，由当前负责人或组织管理员发起。接收人在工作台待办或同一项目页确认，也可以取消；原负责人保留为项目成员，组织角色不变，原里程碑负责人不变。请求有效期 24 小时，接收前重新核对项目版本、成员状态、发起资格及应用权限。项目被编辑、归档或相关人员停用后须刷新并重新发起。网络错误可在原弹窗重试，不会重复转让。

该入口只修改 Kick 负责人并同步 Makit 项目快照，不转让 WeKnow 空间所有权，不发送外部通知。已停用原负责人的接管尚不支持；受管空间继续遵守现有原生权限。版本迁移与本批验收见 [实施记录 07](design/collaboration-framework/IMPLEMENTATION-07.md)。

0.7 的项目编辑请求支持 `requestId`；同请求重试返回原操作及当前项目。改名专用端点与事件回执见 [本批实现](design/collaboration-framework/IMPLEMENTATION-01.md)。

新建并审批的 WeKnow 空间已接入项目成员资格；原有共享空间不自动转换。有效资格还须满足 WeKnow 原生 ACL，移出项目后不能凭旧空间角色访问。升级与撤权边界见 [第二批实现](design/collaboration-framework/IMPLEMENTATION-02.md)。

## 7. 备份与回退边界

- 0.7 增加平台操作/事件表和 WeKnow 受管空间变更，后续已接入受控核心迁移。仅允许已审查计划中的精确基线 / 候选；部分步骤提交后禁止旧二进制运行，须按部署说明继续恢复，不能任意降级。
- 备份需覆盖平台业务/身份 SQLite（使用一致性备份，不能只复制活跃 WAL 的主文件）、两套 PostgreSQL 数据、WeKnow 附件、配置和私有签名/加密密钥。更换组织 ID 或丢失身份库会破坏现有绑定。
- 新增 WeKnow 空间回执表用于防重。其 `down` 迁移明确拒绝删除映射；应用回退不能默认删表或覆盖新写入数据。
- 容器运行器支持完整冷备份、新目录恢复、同 schema 升级、受控 Makit 增量迁移与显式核心迁移计划。迁移失败或中断后，以实际数据库历史核对已提交前缀；同 schema、同计划的修复候选可继续恢复，不自动恢复旧库。未纳入计划的结构变更、任意 SQL 与数据库镜像变更仍拒绝。不要把测试器的临时数据清理用于持久部署。

## 8. 尚未开放的部分

- 本地运行器目前只接受平台、Kick、Makit、WeKnow。历史业务源码保留，不可配置启用；不能把目录中的源码当成可用模块。
- 飞书、OIDC、邮件、旧 GitHub 集成、AI 仍是后续集成，本轮运行器拒绝开启。公共代码来源使用独立的只读开关，不启用这些集成。不再提供 HiFlow 等排除模块的运行入口。
